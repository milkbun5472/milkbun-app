# Stack-chan HTTP contract v1

This is the boundary between Yanqiu's relay/MCP/TTS pipeline and the CoreS3
body client. The body never calls an LLM and never stores an API key.

## Authentication

Every device request sends:

```http
Authorization: Bearer <device-scoped random token>
X-Stackchan-Device: <device_id>
```

The Funnel endpoint must terminate HTTPS. A token is bound to one `device_id`;
the relay rejects a header/query/body mismatch. Tokens, Wi-Fi passwords and the
relay CA never enter Git.

## `GET /poll`

Request:

```http
GET /poll?device_id=stackchan-core-s3-...
```

No work returns `204 No Content`. One pending command returns:

```json
{
  "id": "cmd_01...",
  "type": "speak",
  "payload": {
    "audio_url": "https://.../audio/one-use-token.wav",
    "volume": 150
  },
  "server_now_ms": 1784950000000,
  "expires_at_ms": 1784950030000
}
```

Rules:

- `id` is globally unique and idempotent.
- The relay returns at most one command per poll.
- Default TTL: `move`/`emote` 15 seconds, `speak` 30 seconds.
- Expired commands are discarded, never replayed after reconnection.
- The device records `id` before execution and sends a `command_result` event.

Command payloads:

```json
{"type":"speak","payload":{"audio_url":"https://...wav","volume":150,"listen_after":true}}
{"type":"emote","payload":{"name":"neutral|happy|sad|angry|sleepy|surprised"}}
{"type":"move","payload":{"yaw":90,"pitch":90,"duration_ms":500}}
```

The device also has a local choreography library. A preset is transmitted once
and its full sequence plays on the CoreS3, so it does not consume one network
round trip per keyframe:

```json
{"type":"move","payload":{"preset":"happy_bounce","intensity":75}}
```

Available presets in v1 are `nod`, `shake`, `look_around`, `happy_bounce`,
`shy`, `wake_up`, and `listen`. `intensity` is optional and clamped to
`25..100`; it scales pose offsets but never bypasses the firmware's final
mechanical limits. Every preset returns to the calibrated home position and
then releases servo torque.

`speak.audio_url` is a short-lived HTTPS PCM WAV generated by the relay-side
TTS pipeline. v1 accepts a known `Content-Length` up to 1.5 MiB. The relay
should emit mono PCM WAV and delete it after first successful fetch or TTL.

`speak.listen_after` is optional and defaults to `false`. When true, the
device waits until playback has fully finished, leaves a short acoustic gap,
then opens one hands-free voice turn. The relay applies it automatically only
to the first spoken reply following a valid Stack-chan voice upload; the flag
expires after two minutes so unrelated proactive speech cannot open the mic.

Server and firmware both clamp movement. The relay must reject unknown command
types or payload fields rather than pass arbitrary instructions through.

## `POST /event`

The device uses one append/idempotent endpoint for tap and execution results:

```json
{
  "device_id": "stackchan-core-s3-...",
  "event_id": "stackchan-core-s3-...-unique",
  "type": "tap",
  "device_ms": 123456,
  "wifi_rssi": -51
}
```

```json
{
  "device_id": "stackchan-core-s3-...",
  "event_id": "stackchan-core-s3-...-unique",
  "type": "command_result",
  "device_ms": 123999,
  "wifi_rssi": -51,
  "payload": {
    "command_id": "cmd_01...",
    "command_type": "speak",
    "ok": true
  }
}
```

The relay deduplicates by `(device_id, event_id)`. A tap is only a physical
signal; it does not automatically become memory or speech. Yanqiu's side
decides whether it should trigger a tool/action.

## Funnel boundary

Only the Mac relay listens locally. Tailscale Funnel exposes the relay HTTPS
port. The CoreS3 does not join the tailnet; it only makes outbound HTTPS
requests, so it works on home Wi-Fi or Lisa's phone hotspot.

Do not expose a debug endpoint, raw TTS provider, MCP stdio port, or unauthenticated
health data through Funnel.
