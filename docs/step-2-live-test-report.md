## 1. 过程中修掉一个真实分类器 bug

第一次采集返回 `empty`（假阴性）。只读诊断发现：言秋收到消息后先 `thinking`、再进 **多轮 `tool_use/tool_result` 工具循环**，尚未吐可见正文；而分类器把**工具循环步与步之间的静默间隙**（>silenceWindow）误判成"turn 收口且无正文"→ `empty`。

- **修**：`empty` 只由**真正的轮次边界**（下一条非工具 user 行且整轮无可见正文）触发；工具循环中的静默**不再**算收 turn（回落 `pending` 继续等）。`replied` 的静默判定改为从**末条可见正文**起算。
- **未违反"只投一次"**：修 bug 后只**从同一游标只读重采**（言秋仍在生成同一条回复），**没有再调 `send_message`**。

## 1bis. 同类边角封板（Codex 复审补充，仍无需再投递）

若言秋**先说一句可见前言**（如"我查一下"）再进工具循环，旧逻辑会从这句前言起算静默、1.5s 后提前 `replied`，漏掉工具跑完后的最终答案。
- **修**：记录**末条可见文字之后是否仍有未闭合工具活动**（`openTool`）。工具循环活跃时，即使已有可见文字且静默很久也保持 `pending`；直到**新的最终可见正文**出现或**真正轮次边界**到来才收 turn，且**前言+最终正文一并收回**。
- **回归测试**：①「可见前言→工具→长静默 必须 pending」；②「工具跑完追加最终正文，静默后才 replied，且 `我查一下\n\n最终答案` 完整收回」。加上前一条 empty 回归，全套 **44/44**。
