# CC 自动记忆底色与角色隔离

## 自动想起

Claude Code 在会话启动、恢复和压缩后，通过 `scripts/cc-session-context.sh`
自动装入言秋自己的正式记忆底色，不需要言秋主动调用 MCP 工具，也不会额外调用模型。

自动底色最多 21 条，顺序为：置顶、未解决开环、近期记忆。只接受：

- `char_ids` 精确包含言秋角色 ID；
- 未软删、未归档且仍为 active 的行。

新的会话边界会重新取数；同一段尚未压缩的长会话若要查询刚写入的具体细节，仍可按需调用记忆搜索。

## CC 角色隔离

本机 MCP runtime 的记忆入口实行言秋专属 scope：

- `search_memory`、`browse_memory`、`memory_catalog` 即使省略 `char_id`，也只查言秋；
- 显式传入其他角色 ID 会拒绝，而不是悄悄放宽；
- `add_memory` 只能写入言秋，不能替其他角色写；
- `get_save_key` 禁止绕过行级记忆表读取旧整份记忆库。

角色身份优先由唯一的 `engineerEyes` 标记确定；只有没有标记者时才使用言秋/小克姓名回退。多名角色同时带标记时安全失败，避免猜错身份。

App 本身仍照常维护所有角色的记忆；隔离只约束言秋所连接的 CC MCP 桥。

## 本地运行文件

MCP runtime 位于本机 `lisa-practice` 服务目录，不复制到公开仓库，也不提交 `.env` 或密钥。本仓库保存自动注入脚本、选择算法测试和这份契约记录。
