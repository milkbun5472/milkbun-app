## 推荐顺序

1. **生活事实账本 / 跨模块投影（P1）**
   - 同一件真实生活事实只存一份，带来源、角色、发生时间、真实性（亲历 / 用户陈述 / 推断）。
   - 日记、日程、论坛、朋友圈、查手机、记忆召回只读取各自需要的投影，避免模块各编一份后互相打架。
   - 动记忆写入路径前另开设计闸，本待办不授权直接施工。

2. **角色住所（P2）**
   - 给角色一个会随日程、关系和事件变化的固定空间；先做轻量房间状态，不做重 3D。
   - 房间里的物件与痕迹来自真实事件，不把装饰自动当成事实记忆。

3. **Prompt 诊断台（P3）**
   - 保存每次生成实际使用的上下文清单、来源、裁剪原因和顺序。
   - 支持两次生成的 prompt diff，优先解决“为什么这轮突然不像本人”。

4. **内部 Hook 总线（P4）**
   - 在生成前、解析后、落库前提供受控扩展点，减少继续往大函数里堆条件。
   - Hook 必须有白名单、超时、失败旁路和诊断，不允许静默改写正文。

5. **地图 / 外出冒险（以后）**
   - 可作为线下玩法入口；等生活事实账本稳定后再接，避免先造出第二套世界状态。

- 为了框架统一而整体重写前端。
- 重 3D / 大地图先行。
