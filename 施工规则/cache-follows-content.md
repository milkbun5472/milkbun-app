# 指纹不跟着内容走之前，静态文件不许给长缓存（2026-10-22 白屏事故立）

那天早上一批公共版用户打开是**白屏**。不是哪个功能坏了，是整个 app 起不来。
**是我自己前两天加的那行缓存头造成的。**

## 事情的经过

公共版那些点进去才加载的脚本（`js/lazy-mods.js` 管的那二十几组），
原来每次都从 Cloudflare 重新下，慢。我为了让它快，在 `release.sh` 的 `_headers` 里加了：

```
/js/*
  Cache-Control: public, max-age=86400
```

一天的缓存。只要地址上的 `?v=` 一变，浏览器就会去拿新的——我当时是这么想的。

**可那个 `?v=` 不是跟着内容走的。** `scripts/ship.mjs` 只给**这一版动过的文件**
bump `?v=`；而公共版每次发版都会把**所有**脚本重新压一遍。
于是出现了这种组合：

- `bundle.js` 是今天的（它每版都变，指纹跟着变）
- `js/xxx.js?v=76.2xx` 这个地址一个字没变，浏览器**直接用昨天缓存里那份**

今天的 bundle 调昨天的模块，对不上就当场抛错——白屏。

**我那一步只问了「怎么让它快」，没问「这个指纹到底是跟着什么变的」。**

## 规矩

**给任何静态文件加缓存（或者把时长调长）之前，必须先证明它的指纹是
【从文件内容算出来的】。证不出来，就不许加。**

现在的做法在 `patches/bind-scripts.mjs`：lazy 脚本的 `?v=` 换成了**内容哈希**，
内容没动指纹就没动，内容一动指纹必动——这才配得上一天的缓存。

加缓存那一轮要同时答出来的三句：

1. 这个 `?v=`（或文件名里的指纹）是谁写上去的？版本号还是内容哈希？
2. 发版时**没改的那些文件**会不会被重新生成成不一样的字节？会 → 版本号指纹立刻失效。
3. 一个用户手上**半新半旧**地拼起来，最坏会怎么样？白屏还是只是某一块不灵？

## 判据一句话

**同一个地址，今天和昨天拿到的字节会不一样吗？**

会 → 不许给长缓存（或者先把指纹改成内容哈希）。
不会 → 才可以。

## 顺带记下的一条

**「我只是让它变快一点」是最容易漏掉回归的那种改动。**
功能改坏了通常只坏那一块，缓存改坏了是整个 app 不开机，
而且**只坏在用户那边**：我自己的浏览器一刷新就是新的，本地永远看不出来。
这种改动验收不能只看自己点得开，得去真线上**先 unregister SW、清掉 caches**，
照一个老用户的样子打开一次。
