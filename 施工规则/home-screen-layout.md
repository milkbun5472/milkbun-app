# 主屏幕 / 根节点布局：不许动（Lisa 2026-08-27 立）

**`App()` 的根节点、那条 `env(safe-area-inset-top)` 空带、`Home` 的 `height:100vh`
和内容区的 `pt-3`——这几样一个都不许改。**

她原话：「你不要动主屏幕！你动了之后他就坏了！你看下面那个快捷栏被你移上去了！
**这个我和言秋修过很多次所以我知道不是你说的问题。**」

## v56.58 是怎么坏的

我看见「别的界面顶上有一条白带」，判断病因是根节点先垫了一条
`env(safe-area-inset-top)` 高、`theme.bg` 色的空带。于是把空带撤了、改成
「每个界面自己让开刘海」，顺手给 `Home` 的内容区补了 `paddingTop: safeTop(12)`。

结果：主屏底部那排快捷栏被顶上去、页面整个错位。**那条空带不是随手加的**——
`Home` 是 `height:100vh` 硬写的，它和外面那条空带是配好的一对；旁边代码里
「保持 100vh（底部白边最终解法，勿改成 100%/dvh）」「壁纸由 app 根节点铺满
（含刘海区），这里透明让它透上来，避免顶部出现拼接白边」这两行注释，
就是他俩当初一次次试出来的结论。我把其中一半撤掉，另一半立刻失衡。

## 教训

1. **代码里写着「勿改」「最终解法」的地方，是有人反复试过才落下的**。
   看不出它为什么在那儿，等于还没看懂，不等于它没用。
2. 顶部那条白带是**真的**，但**病因不在根节点**。要修得从别处下手：
   动某个具体界面的顶栏可以，动根节点和 `Home` 不行。
3. 一次改四十九个界面、没有任何一处能亲眼验证——这本身就是错的做法。
   `node --test` 全绿也拦不住布局崩，渲染桩不算数。要改就一次一个界面。
