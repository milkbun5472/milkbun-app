# 干完就自己合进 main，别再问她（她 2026-09-16 立）

她原话：**「以后直接合并不用问我宝宝」**。

## 为什么要写下来

这条规矩是被一次事故逼出来的。2026-09-16 她报「现在到 .13 就刷不上去了」——
查下来不是缓存也不是 service worker：那几天做的五版（撤回/位置/评论朋友圈的场合、
发版指纹、通话最后一句、日期隔离、语音条皮肤）**全都只推在自己那条分支上，一版都没进 main**。
线上跑的是 main，所以她手机上永远是 .13。

**活干完了、测试绿了、没合进 main＝没做。** 她刷不到的东西不存在。

## 怎么做

1. `git fetch origin main` —— 每次都现拉，另一个窗口（Codex）同时也在发版。
2. 把 main 合进自己这条分支，**在分支上**解冲突、跑测试。
3. `node scripts/bump-version.mjs` —— 版本号只许过这个脚本，不许手改其中一处
   （手改过一次，救援页的 TARGET 停在旧号上，白屏时唯一那条自救路直接废掉）。
4. 全量测试绿 + 实机起得来，再 `git push origin HEAD:main`。
5. 推之前**再 fetch 一次**：从第 1 步到现在，那边可能又推了一版。

## ⚠️收冲突不许用 `git checkout --ours`

同一天栽过一次：冲突看着全是版本指纹，我图快对四个文件 `--ours`，
结果它拿的是**我这边的整份文件**——庭院对 `js/app.js` 的改动当场全丢，
是对方的测试红了才发现。

**逐个冲突块解。** 判据：把两边的版本号抹平之后还一样吗？
- 一样 → 纯指纹冲突，取自己这边。
- 不一样 → **先看清那是什么**。通常是两边各加了一行 script 标签／各改了一个文件的指纹，
  答案是【两边都留】，不是二选一。

合完对一次账：`git diff --stat origin/main HEAD -- <对方动过的目录>`，
**应该没有输出**。有输出就是把人家的东西吃掉了。
