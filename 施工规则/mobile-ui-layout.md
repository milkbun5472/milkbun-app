# 移动端界面铁律（所有施工窗口必读）

这份规则来自 Lisa 已反复调好的主聊天界面。以后做任何 App 内页、小游戏、查手机或设置页，都以现成聊天界面为标尺，不要重新发明顶栏、底栏和安全区。

## 1. 顶栏

- 顶栏自己吃 `safe-area-inset-top`，内容使用公共 `safeTop(px)`；不要在页面外壳另垫一条状态栏空带。
- 普通子页面使用紧凑标题栏：返回键、居中小标题、右侧等宽操作位。禁止再放 30–40px 大标题和大块上下留白。
- **那条紧凑栏就是 `js/components.js` 的 `Head`**（`zh` 标题 / `sub` 或 `en` 副标题 / `right` 操作位）。
  别再自己写一条 —— v61.27 之前 `Head` 自己是「30px 大标题」，于是每来一页都得重新想起这条规矩、
  再手写一份紧凑栏；漏掉是常态（她 2026-09-03：「你怎么老是忘」）。
  病根不是记性，是这条规矩当时没有落点。现在改 `Head` 一处，六十多页一起合规。
- 主屏是唯一例外，详见 `home-screen-layout.md`。

## 2. 底栏

- 以主聊天输入栏的 `COMPOSER_PAD_BOTTOM = calc(env(safe-area-inset-bottom) * 0.4)` 为高度标尺。
- Tab bar 也只吃 `0.4` 条底部安全区；不得使用 `env(safe-area-inset-bottom) + Npx` 把底栏垫高一截。
- 图标、文字和上下 padding 合计应接近 54–60px（不含极小设备差异），禁止为了“保险”重复叠加安全区。
- 新底栏优先复用已有 SVG 图标体系，不用 Unicode 方块、爱心字符等临时图标。

## 3. 滚动与详情返回

- 列表进入详情前必须记录列表 `scrollTop`；关闭详情后恢复原位置，不能跳回顶部。
- 横滑容器保留自身横向位置；详情返回不得重建整页数据或切回默认 tab。
- 页面只允许一个负责该区域的主滚动容器，顶栏和底栏 `shrink-0`，正文 `flex-1 min-h-0 overflow-y-auto`。

## 3.5 底纹铺在【外壳】上，顶栏透明（2026-09-03 立）

页面有底纹（木纹、纸纹、壁纸……）时，那层底纹要铺在**最外面那个 `h-full flex flex-col` 的外壳**上，
`Head` 传 `bg: "transparent"` 让它透上来。

铺在滚动区上是错的：顶栏那一条还是平色，底纹从它下面才开始，**顶上横着一道没盖住的带子**。
（跟主屏壁纸铺在根节点上是同一条道理，见 `home-screen-layout.md`。）

⚠️底纹还要**不跟着滚**：别挂 `backgroundAttachment: "local"` —— 内容在动，底不该动。

⚠️深色/自定义主题下 `t.ink` 可能不是六位色号，拼 `t.ink + "18"` 这种透明度后缀会拼出废值，
整层底纹静默消失。先验一下再拼，验不过就退回纯色。

## 4. 动手顺序

1. 先找到主聊天里同类顶栏、输入栏或列表结构。
2. 抄同一套安全区公式和 flex 层级，再换业务内容。
3. 用窄屏检查顶部不越刘海、底部不抬高、弹层可滚动、详情返回位置不丢。
4. 给关键公式和交互补静态/行为回归测试，发版前运行。

## 5. 当前权威参考

- 顶部安全区：`js/engine.js` 的 `safeTop()` 说明与主聊天顶栏。
- 底部高度：`js/engine.js` 的 `COMPOSER_PAD_BOTTOM`，以及 `js/components.js` 的主聊天 composer。
- 容器层级：主聊天的 `h-full flex flex-col` + 正文 `flex-1 min-h-0 overflow-y-auto`。

如果设计稿与这些铁律冲突，以 Lisa 当轮明确要求为准；但必须说明冲突，不能悄悄自创第三套。
