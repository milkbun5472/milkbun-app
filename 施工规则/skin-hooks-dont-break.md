# 动挂点、动结构之前，先想别人的美化会不会坏（她 2026-10-19 立）

她原话：**「我们做美化改动要考虑搞了一份会不会导致别的坏掉」**

群友的美化 CSS 散在各人手上，我们看不到、也没法替她们改。app 一改结构，坏的是她们，不是我们的测试。

## 动手前问三句

1. **挂点名字、`data-me`/`data-kind` 这些属性**：只许加，不许改名、不许挪走。
2. **层级**：美化常写 `A > B`、`div:has(> 气泡)`、`:nth-of-type`。
   给某个元素外面多包一层、或拆掉一层，写过子选择器的那份就失效。
   要包，就包成**跟同类元素已有的层级一样**（例：正在输入那颗气泡跟普通消息一样外面包一层），不是另起一种。
3. **定位和层叠**：我们改了 `z-index`、`position`、`overflow`，美化里的 `box-shadow`、负 margin、伪元素
   会不会因此盖住别的东西、或被别的东西盖住。

## 判据一句话

**一份照现在挂点写好的美化，换上这一版以后，长相和手势还一样吗？**
不一样 → 要么改成兼容的写法，要么在攻略里讲明白怎么改，不能悄悄让它坏。
