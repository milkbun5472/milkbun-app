# 同一个形状先开公共的，已有的也搬过来（Lisa 2026-09-06 立）

她原话：**「以后这种形状能不能都开公共然后合在一起而不是照着已有的新开，
不然以后改很麻烦。」**

## 事情长什么样

她报 api 站子 24 小时用掉 8 块、一次一分钱、而她那天只在修 bug。
实测出来就是 800 次那个量级：**自动补刷失败之后没留下任何痕迹，
于是每刷新一次就把所有角色重打一遍**——三个角色、什么都不点、连刷四次
就是 12 枪 12 万字。

而这件事**六条链里有两条早就修对了**：查手机（先记游标再刷）和角色日程
（成败都记、两小时冷却、封顶三次）。它们的注释里甚至写着为什么要这么做。
另外四条（日记、钱包、月度印象、心上）一条都没跟上。

**病根不是那四条忘了，是那两条把规则写在自己家里。**
一份规则住在某个功能内部，别人只能【照着抄】——抄的时候就是各自一份，
从此三处各改各的，改一处永远漏两处。

## 规矩

**发现同一个形状要在第二处出现时：先把它抽成公共的一层，然后把【已有的那几处
也搬过去】。不许照着已有的那份在新地方再写一遍。**

搬这一步是重点。只开公共的、旧的留在原地，是最坏的一种：
从此同一层规则活在【公共那份 + 旧的那几份】，比原来还多一处。

判据一句话：**这条规则现在写在几个地方？**
超过一个 → 还没搬完。

## 已经这么做了的

| 公共那一层 | 收了谁 |
|---|---|
| `js/auto-gate.js` 的 `AutoGate` | 日记 / 钱包补账 / 月度印象 / 心上 / 角色日程 / 查手机 —— 六条自动补刷的闸 |
| `js/auto-gate.js` 的 `ApiMeter` | 记账只数在 `callAI` 那**一处**：全库所有调用都从那儿过 |
| `js/components.js` 的 `Head` | 九十来页的顶栏（v64.90 / v64.95 把 screens.js 和 phone.js 里手写的那五十多条搬了过来）|
| `js/components.js` 的 `requestAppConfirm` / `requestAppPrompt` | 全库十几处原生 confirm/prompt |
| `js/auto-refresh-policy.js` 的 `FEATURES` | 那十二项自动刷新的名字——`AutoGate.labelOf` 直接问它要，不另存一份 |

⚠️名字也算规则：`AutoGate.labelOf()` 没有自己写一张「diary→日记」的表，
而是去问 `AutoRefreshPolicy.FEATURES`。**另存一份表就是又开了一处要同步的地方。**

## 搬的时候不许顺手改行为

公共那一层要能表达【原来那几处各自的分寸】，而不是把它们抹平：

- 查手机一次是十五枪，所以它要的是「**先占坑**、成不成都不重来」
  → `AutoGate.claim()` + `{ maxTries: 1 }`，不是默认的重试三次。
  抹平成默认档的话，一次失败会变成 45 枪。
- 日程一次是一枪，重试三次是划算的 → 走默认档。

**同一把闸，两种用法**；不是两把闸，也不是一把闸把两边都将就了。

## 记账那一层的两条

1. **数在【发出去】那一刻，不是进函数那一刻。** 没填密钥、地址填错这些压根没发出去，
   中转站不收钱；数进来就成了比账单还大的假数（第一版就是这么写的，实测 2 枪记成 6 枪）。
2. **说不准的时候记「其它」，不许猜。** 两件活儿同时开着时，那一枪算给谁都是瞎猜——
   `currentTag()` 直接返回空。**一个记错的数比一个诚实的「其它」有害得多。**
