# 绒绒小镇

小世界中的第三个正式入口，沿用 `x_fairyGarden`／`x_fairyGarden::角色::房间` 的旅程存档与原备份、云同步。庭院、列车、宠物的进度分别位于 `worlds.garden/train/pets`，同一档的身份、同行者、journey、聊天记录保留；原 `world` 仍只镜像庭院。新宠物房间沿用选角色、建房间与记忆权限流程，不额外新建一套宠物存档键。

第一次进入可实时预览并设置名字、五种毛色或自选底毛/花纹、胖瘦80–125%、大小70–130%。胖瘦只改变身体网格的宽度，脚爪与头脸保留，大小等比缩放。眼、鼻和耳内继续受原UV蒙版保护。草稿不自动落盘；确认成功才进入街区，取消恢复已保存的设置。不同档的宠物外观独立，刷新和跨世界回来保持已保存的宠物。可以选择猫咪或狗狗，两者共用街区与室内；种类也按存档独立保存。

默认进入公园街区，点地面绕障走路、拖动与双指缩放；六栋房子可走到门口进入家里、面包店、花店、便利店、咖啡店和侦探小巷，出门恢复门外位置和视角，室内点家具和近距离看猫。宿主「去别处」可以改宠物、回同档庭院/列车或选另一档；庭院花册、列车下车页也能进入同档宠物世界。

进度每3秒、走到目的地、进出屋和离开时保存。后台停止行走，保存失败暂停新操作并阻止离开，重试成功再继续。身份校验阻止已切换的存档被旧iframe写入。屋内照料、角色共养和第一份面包店职业按同档保存，见下文。

## 资源与压缩

正式游戏直接复用 `art/pet-career/preview.mjs` 渲染器、现有猫运动/UV染色、庭院寻路和手势、共用室内镜头，不复制模型或渲染器。现有派生GLB已经使用Draco压缩并按区域/材质合并；猫为283964字节、狗为339724字节、最大1K的WebP贴图，街区625444字节。正式入口染色蒙版再由899691字节PNG压成366706字节无损WebP，解码RGBA逐字节相同；眼鼻保护不变。可重跑 `scripts/compress-pet-assets.py`，报告在 `compression.json`。每间屋独立加载，退出释放其网格/材质/贴图，街区保留用于返回；建模脚本、Blender源与测试不进入游戏下载。应用像素比限制1.5，静止时按需渲染。

`scripts/build-fairy-garden.mjs` 已把 pets 和共用宠物资产加入现有庭院/列车资源图，统一按内容产生缓存指纹；SW分别缓存各iframe文档及同源资源。仅缓存已访问的资源，未访问房间不保证离线可用。

## 屋内照料（第一批）

家里六个按钮对应添粮、零食、玩球、小老鼠、休息和摸摸；点饭碗/玩具篮/窝/沙发或宠物也可以互动。实际行走复用庭院导航器，按现有家具脚印避障，身体大小决定边距；吃饭在碗边消耗碗内粮并恢复饱腹、零食单独喂一小口、吃饱会拒绝，玩耍在地毯追移动玩具消耗精力/提高心情、休息在窝或沙发边躺下并恢复精力，摸摸慢慢提高亲人倾向。睡觉时要叫醒才能换活动，太累不想玩、连续摸会挪开，碗内有粮不重复加。无金币成本、健康惩罚或付费AI。

闲着12秒后会按饱腹/精力和活动倾向自行吃饭、休息、追玩具或看窗外；自主看窗外可被玩家互动打断。`care.mjs`共管有边界的数值、任务/阶段/时间、种子随机、性格/玩具/休息偏好、最近8件小事，存在原worlds.pets.care；旧档默认补齐，恢复进行中的活动。状态只按可见前台时间推进，背景/设置/去处/「看看它」暂停，不根据墙钟补算离线。保存失败暂停操作，重试成功再继续；仍按档与角色房间隔离。

「看看它」复用宿主Head与整页单一滚动正文、原0.4底部安全区：饱腹/精力数值和进度条、心情/当前行为文字、脾气/偏好文字、游戏经过时间的小事。不在iframe另造标题栏。菜单可进入，游戏顶部也有入口；外面可从状态页回家照料。`care.test.mjs`检查旧档/坏档、移动不给奖励、可见时间/暂停、偏好与拒绝、自主选择、0.7–1.3大小所有家具路径；`pet-care-browser.cjs`作为原第三世界浏览器回归的一部分检查真实行为/布局/暂停/活动刷新。

## 面包店职业与小金库

`worlds.pets.career` 保存愿意/拒绝、一次零食再邀请、三段试工及当前事件、工作印象、收入、物品、账本与履历。每天最多一班；五分钟前台照料时间算一天，后台、菜单、离线暂停。面包店与花店共用workplaces注册表和职业引擎，工作只在实际进入的所选小店推进，事件需玩家或TA从当前选项拿主意；三件完成后手动收工才能结算一次。疲劳暂停，可回家恢复或中止不结工资；旧照料档从当前游戏日开始，不伪造既往工作或休息历史。猫狗共用职业规则，意愿受各自精力/心情/亲人倾向/工作印象影响。

工资只进宠物自己的 balance，账本记录每班收入及买零食/自己的球。带回的小面包和零食在 inventory，太饱或忙着时不能喂。小球所有权直接决定玩具角是否摆出自己的球，点击复用原玩球流程，球与主动叼玩具共用同一实物及toyPlaces位置，不另摆一颗重复球。`home-souvenirs.mjs` 从同一库存/履历投影出饭盆旁的面包篮、小球、首工纪念；面包篮使用Three程序几何、纪念使用一张现场生成的印刷纹理，不增加GLB或下载图片。分零食/小面包只在家中开始原进食流程，接受后扣一次库存，task.food随档保存，走路不加饱腹，实际吃时逐渐恢复；离家取消已分出的这一份，不再重新扣。firstTrial在首次实际收工时保留实际职业、日期、当时名字、收入、该职业带回的物品与三项实际决定和决定者，独立于短近期日志；旧档只从首工履历原记录恢复日期和工资，缺的当时名字、面包数量和主意留空，不补造。纪念可从墙进入原履历整页，TA沿原聊天事实读同一投影，无AI自动调用。花店三段事件从花瓣/包花丝带/门口邻居/收工小花四种故事选择；两店工作印象与首工状态分别保存，一天共用一次邀请和一班，拒绝后不能换店重抽。花店工资18/24加酬谢，带回小花和花瓣；实际选认识邻居才保存friend记录。回家arrange消耗一枝花，vase最多三枝，与库存一起回滚和存档；花瓶用现有窗边桌与轻量程序几何，聊天home事实从同一vase/inventory投影。其他职业、TA自行找兼职暂未实现。

动作窗口的接口：`PetGame.career()` 为独立只读快照，job.phase 为 working/choice/ready/tired，event.id 精确标识当前决定。`PetGame.careerAction(action, options)` 执行邀请/再邀请/选项/收工/购物等，由共用纯状态引擎校验并落盘；保存失败回滚职业和照料变化，冻结到重试成功。成功或拒绝后发出 iframe 内 `pet-career-change` DOM 事件，detail 含 action/accepted/text；动画消费事实，不重复结算。职业引擎不修改骨骼或姿态。

TA建议共用原 ask、房间上下文与记忆权限，手动发送一次才请求模型。work-choice 只接受本次世界事实里的事件及选项；应用时再次校验当前事件，迟到/无效主意不会写进另一件事。实际选项注明拿主意的人，聊天返回职业页再回场景继续。

`career.test.mjs` 检查拒工随机持久化、邀请门禁、三阶段、前台/地点暂停、刷新事件、重复结算、库存购物、取消与休息记录。`PET_CAREER_CHECK=1` 开启完整宿主浏览器职业回归，涵盖猫狗、320/390/430、TA决定、刷新、失败保存回滚与三世界往返；不使用真实私档或付费模型。

## 主动找人

家里闲下来后，猫狗会按真实饱腹、精力和分别相处的经验选择找谁：空碗旁等饭、看碗再回头看人；先低头拿起球或小老鼠，嘴部挂点随完整头骨移动，走到脚边低头放下；主动贴近蹭蹭，等回应时伏低身体，真正摸完会自己走开；困了挑一人在旁边伏身睡，休息完成才增加靠着该人的经验。用户仍在屏幕外操作，前侧保留不可见的用户寻路位置；不再显示「你这边」地垫或「在家陪着它」浮动文字，同伴则使用实际小人的当前位置。

`initiative.mjs`仅从真实照料经验计算选择权重，不预设两人的养育分工。`care.mjs`保存目标、取/叼/放/等阶段、玩具的实际落点、你与每位同行者的零食和靠睡经验。来访只在到达、玩具放下后记录，拒绝或途中取消不奖励。喂过零食后可能来讨一小口，爱玩与亲人倾向影响主动邀玩/贴贴；有粮先吃，休息和等待保留边界，摸够或等待超时会走开。

同伴对实际到达的请求可以在场景中回应，叼来玩具后就地陪玩、贴近后摸摸，饿了走去添粮。聊天沿用当前世界事实及既有权限，知道最近的真实来访；feed/play/pet/snack通过相同照料入口执行，不额外自动调用模型。暂停菜单/后台/保存失败时行为不推进，重载叼取中途接回同一阶段，不重复来访或照料结算。`PET_INITIATIVE_CHECK=1`开启宿主浏览器专项验证；单测为`initiative.test.mjs`。

狗狗与猫咪共用外貌设置：去别处→宠物名字与外貌，自选底毛/花纹、胖瘦80–125%、大小70–130%，确认后按档保存。「复位」保留当前物种，恢复原毛色和100%体型。

## 宠物页面的材质与书页

宿主 `panels.css` 只作用于 `.pet-session`：照料名牌/记录、两张工作启事及面包店/花店试工单、零钱袋/小票、履历册、街区路牌与旅程明信片，毛色与种类决定旁边的小头像。职业生活册用贴页索引分今天/钱/履历，支持键盘方向键；每张书页及去处页独立记阅读位置，从TA商量或子页回来恢复。一份PetPanel负责整页正文和0.4安全区底栏；沿用Head，iframe保持挂载并暂停，打开整页时隐藏画面以露出外壳纸纹。外貌控件仍在实时模型下方，按原预览协议保留模型。没有改数值、职业结算或模型动作。

`PET_PANEL_CHECK=1` 的浏览器回归检查猫狗320/390/430，状态/三张书页/去处、头栏、单滚动、底栏尺寸和逐层返回位置；职业回归同时覆盖新聊天页和实时选择。

## 同一档的多只宠物

`worlds.pets` v4 的 `pets[]` 是唯一名册，每只拥有稳定 `id`，独立 `profile/care/career/configured`；`activePetId` 选择当前照料、出门和打开面板的对象。原顶层 profile/care/career 是当前对象的兼容投影，不是第二只宠物。v3 无名册旧档迁入一条稳定记录，保留原外貌、关系、任务、偏好、金库与履历；重复载入不重复迁移。较大备份不截断其名册。新迎接上限四只，个体随机种子与起始活动/社交/胆量各自生成，后续性格来自实际照料。

「去别处 → 家里的宠物」或场景左侧名字牌打开名册；卡片打开该只照料记录，另有名字外貌和职业生活册入口。每页阅读位置按宠物id分别保留，返回名册恢复原位置。新宠物在家里预览后确认才加入存档；取消、保存失败不覆盖原有宠物，重试不会重复领养。

四只在同一客厅共用一个渲染器，各自骨骼、体型网格、染色uniforms、状态和任务独立；原两种模型/纹理只加载一次，共享源纹理，不复制下载或重建GLB。第一只用原饭盆和窝，另三只用各自饭盆/垫子/玩具起始位置；简单局部避让与接近目标留位。点场景中的另一只先选中它，再点才摸摸；六个照料键归当前选中对象。TA同时只执行一次照料，按真实抵达请求选对象，helper.job.petId记录实际宠物；聊天facts.pets提供全家各自事实，动作petId选择对象，缺省沿发送时选中的id。

出门仅当前一只跟着走，其余留在家里并暂停状态消耗；回家恢复各自位置与状态。原庭院/列车、房间认知权限、聊天记录和备份存档钥匙不变。验证见`household.test.mjs`与`scripts/checks/pet-household-browser.cjs`。

`florist.test.mjs` 和 `PET_FLORIST_CHECK=1` 覆盖共用引擎的职业隔离、拒工/换店限制、实际小店暂停、花店三件事、邻居与花/花瓣、回家插瓶消耗/上限/保存失败回滚/刷新、去除两处场景标签和窄屏书页。浏览器专项接在既有职业流程后，需同时 `PET_CAREER_CHECK=1`。

## 它自己花钱

`shopping.mjs` 是玩家手动购买与宠物自己挑的同一商品表和购买校验。`career.shopping` 独立保存每只的 enabled（默认开启）、cap（8/12/24，默认24）、rng、lastDay、实际小票与真实待带回小袋子；不共用工作随机序列。实际便利店 `store` 里前台逛12秒，性格、当前饥饿、真实照料/玩球经历影响零食/歪眼球/纸箱的权重，始终能选择留钱，每只一天一次；菜单/后台/离线、正在工作或忙着照料不推进。只有 checkout 在共用 careerAction 事务中扣钱；失败同时回滚余额、购物种子、日志及照料。已付待带回的球/箱也占所有权，不能重买，关开关不丢已付袋子。

回家 unpack 在同一事务中把实际袋子放入库存，重复/刷新不重领；家里每只自己的待拆袋子均能收妥，不改变当前选中对象。零食尝试按原进食任务分出1份，走路不恢复饱腹；满或忙则保留2份。歪眼球在原实物上添轻量眼睛，原玩球/叼球/落点共用；纸箱是每只 home 的轻量几何，点实物或零钱袋按原 sleep 行走/实际休息，care.task.place=box、rests.box保存并只在完成后增加偏好。原骨骼/姿态算法保持。聊天沿现有 pets/career/home 投影知道自己花钱的事实，无新增模型调用。用户需陪着实际到店，尚未做宠物自行离家。

`shopping.test.mjs` 与 `PET_SHOPPING_CHECK=1` 浏览器专项验证开关/额度、独立随机序列、前台地点/暂停/刷新、失败回滚、一次扣款、待回家所有权、实际玩球/纸箱休息/零食进食及聊天事实；专项接在花店后，需同时 PET_CAREER_CHECK=1、PET_FLORIST_CHECK=1。
