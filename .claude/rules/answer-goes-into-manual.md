# 答了群友的问题，攻略也要跟着改（她 2026-10-05 立）

她原话：**「我发别人的问题你回答了，就算不改代码也要顺手在攻略里面改，没有就新开一个条目放到合适的位置。要注意日常维护。有时候是要改而不只是在一长串后面加一堆。」**

放在这儿（不放 `施工规则/`）是因为它管的恰恰是【不改代码】的那种轮：只答疑的窗口不会去翻施工规则。

## 规矩

她转来别人的问题（截图、「群里问」「有人说」），我答完以后：

1. 去 `js/assistant-manual.js` 找讲这块的那一条，把答案写进去——**秋秋和攻略读的都是这一份**。
2. 没有讲这块的条目 → 新开一条，`APPS` 里挂到它该在的那一组、那个位置，不是一律堆在最后。
3. **是维护，不是追加**：原来那段说错了、过时了、跟这次答的对不上，就改那一段；
   同一件事已经写过，就合进去，别在一长串后面再挂一句「另外……」。
4. **只改攻略不发版**（她 2026-10-05：「只推攻略不用发新版数字，直接推 main，等后面更新改版自然会更新」）：
   这一轮只动了 `js/assistant-manual.js` 的条目文字时，不 bump 版本号、不动 `STAMP`、不改 `?v=`，
   跑一遍测试和 `git diff --check` 就直接推 main。下一次有人正式发版，指纹一换就带上了。
   同一轮还改了别的代码 → 照常发版，`STAMP.entries` 把攻略那几条 id 一起写上。
5. 写进攻略的话要**说一类事，不说这一个人的这一回**：群友丢的是世界书和地图，写的是「东西突然全没了」，
   别把她那次丢的那几样点名写进去。

6. **攻略只写给最新版看**（她 2026-10-08：「有没有可能攻略就是给最新版看的呢」）：
   写「现在它怎么样、遇到了怎么办」，不写「旧版本有个 bug」「更新一下就好」「以前会……现在修好了」「v7x.xxx 之前」。
   修掉的毛病，最新版里已经不存在了，就不该再占攻略一行。只有用户手上**真留着旧数据**要处理时（比如丢了的往期要放回去）才写，
   而且写成「遇到这种情况怎么办」，不讲版本史。

判据一句话：**下一个人问同样的问题，秋秋翻手册答得上来吗？** 答不上来＝这轮没做完。
