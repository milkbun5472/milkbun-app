# 四层手机数据模型（Codex 提，2026-08-29 立）

查手机的刷新是**整份重生成**。什么该保、什么该换，不是一个开关，是四层。
不分层会同时得两种病：**刷一次换个人**，和**三个月后变成只进不出的数据坟场**。

| 层 | 常量 | 行为 | 收什么 |
|---|---|---|---|
| 🔒 硬钉死 | `PHONE_STICKY` | 除非手动改，永远不变 | 号码、账号 id、过敏与真忌口 |
| 🌱 缓慢演化 | `PHONE_EVOLVE` | 默认沿用，有理由才变，一次最多动两项 | 昵称、签名、给她的备注、**对她的评价**、住址、消费习惯、口味偏好 |
| 📚 累积日志 | `PHONE_GROW` | 新旧合并去重，满了挤掉最旧的 | 通话、便签、订单、搜索、看过的、照片 |
| ♻️ 当前快照 | 不登记 = 默认 | 每次照实重写 | 购物车、在途、开着的标签页、今天的健康、**名册** |

## 判据两问

**一、这一栏变了，是「他变了」还是「系统忘了」？**
系统忘了 → 🔒 或 🌱。他变了 → 🌱 或 ♻️。

**二、它说的是「发生过什么」还是「现在有哪些」？**
- 发生过 → 📚。**只进不出是对的** —— 发生过就是发生过。
- 现在有哪些 → ♻️。**名册必须能出。**

第二问是 Codex 抓出来的那个病：我原来把「常联系」和「黑名单」也做成了累积，
于是**拉黑只进不出，攒成一座坟场**。同理「关注列表」会取关。
这三样都是名册，不是日志。

## 🔒 和 🌱 的分界

**「对你的评价」绝不许硬钉死。** 钉死等于关系长了，他还拿第一次见面的眼光看你。
备注和昵称同理：恋爱、吵架、和好都会改。

**地址也不许硬钉死** —— 会搬家，也会多出「她家」那一条。

**口味要拆开**：过敏和真忌口是身体的事 → 🔒；喜欢什么、预算、习惯是心情的事 → 🌱。

一句话：**只有换个人才会变的，才配进 🔒。**

## 🌱 靠什么保证它不退化成 ♻️

提示词里说「默认照抄回来，有理由才改」只是**降概率**。模型高兴起来能把六项一起换掉。
所以代码这一道必须有：

1. **空值不许抹掉旧值** —— 模型漏写一项，那一项保留。
2. **改动上限 `PHONE_EVOLVE_CHURN = 2`** —— 一次刷新最多真改动两项，超出的按旧值回填。

这是「规则降概率，代码才保证」在这一层的具体落法。

## 存进去的顺序

```
🔒 phoneKeepIdentity → 🌱 phoneEvolveMerge → 📚 phoneGrowMerge
```
剩下没登记的一律 ♻️。顺序不能换：先钉死身份，再收口演化，最后并日志。

## 还没做的（Codex 提的，欠着）

- **名册的退出机制（墓碑）**：书签取消收藏、草稿发布或删除、关注取关、
  书换书架或读完移出。现在这几样要么纯累积（出不去）要么纯快照（会整批换）。
  正解是让模型显式给一份 `retired`，累积层据此剔除。
- **相册五类配额**：每次生成要保证五类都还在，不被旧数据挤到只剩一两类。
- **相册语义判重**：现在只按标题+日期认人，同一张照片换个说法就会攒两份。
- **健康的趋势**：全部 ♻️ 是对的（它代表今天，不是病历）。真要留趋势，
  该另存每日轻量快照（综合分 + 5~10 个核心指标），不是把整份报告天天累计。
