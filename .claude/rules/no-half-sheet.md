# 默认不要半窗（Lisa 2026-08-30 立）

她原话：**「顺便写一份提醒放任何施工的都能看到，默认不要这种半窗。」**

「半窗」＝从屏幕底下掀起来、只占下半屏、上面那半糊着一层背景的那种面板。
代码里就是 `h(Sheet, {...})`（`js/components.js` 的 `Sheet`：`absolute inset-0 flex items-end`）。

**做任何新界面，默认用整页，不要用半窗。**

## 为什么

她 2026-08-30 在【去处】里点开一块区域、再点开一件东西，两层都是半窗，截图报回来的样子：

- 一块区域里有三件东西，标题「衣柜与玄关过渡角」占掉一行半，剩下的位置只够干列三个名字，
  每件东西的说明一句都放不下——**内容被挤到下半屏，等于自己把可用高度砍掉一半**。
- 上面那半屏糊着的是【上一层的界面】，不是留白。看上去像是没加载完，不像是一层新的东西。
- 一层半窗上面再掀一层半窗，可用高度再砍一次，第二层就只剩几行。

半窗的代价是**固定的**：不管里面装多少，先扣掉一半屏幕。而这个 App 里的内容
（一段话、他的想法、一列东西）**几乎没有一样是三行能说完的**。

## 判据一句话

**这一层的内容，需要同时看见它下面那一层吗？**

- **不需要** → 整页。绝大多数都是这一类：详情、列表、一段正文、一个子页面。
- **需要** → 才配用半窗。真正合格的例子只有两种形状：
  - 选一下就走的（选个日期、挑个人、二选一确认），而且**下面那一层正是它要修改的东西**；
  - 一两行字的确认/提示，多一个整页反而更重。

拿不准就用整页。**整页从来不会因为"内容太少"而出错，半窗一定会因为"内容太多"而出错。**

## 整页该长什么样

照【去处】里区域页和物件页那两页的做法（`js/dwell.js`）：

- `h-full flex flex-col`，顶栏 `shrink-0`，正文 `flex-1 min-h-0 overflow-y-auto`
- 顶栏是紧凑标题栏：返回键 + 居中小标题 + 右侧等宽操作位（见 `mobile-ui-layout.md`）
- 上一层如果有图，就把那张图糊开压暗当底衬——接得住上一层，又不抢正文
- 一层层退：物件 → 区域 → 那处地方 → 列表，返回键每次只退一层

## 已经写好的那些

App 里现存的半窗有九十多处，**这条规矩不要求回头一次性改完**，
改到哪一处、哪一处顺手换掉。但**新写的一律按整页来**。
