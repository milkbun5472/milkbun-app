# 叫她删东西之前，先叫她导出（2026-09-04 事故立）

那天她的存档丢了两次，**两次都是我的指令直接造成的**。

## 事情的经过

图标换了她看不见，我判断是 iOS 把已装 app 的图标钉死了，于是说：

> 「手机上先把 app 长按删掉，再重新 run。」

她照做了。**那个原生壳里的 localStorage 和 IndexedDB 是跟 app 一起走的** ——
删 app＝清数据。我说那句话的时候，脑子里只有「图标缓存」这一件事。

然后她想找回数据，打开了一台几个月没用过的网页版。那份旧存档**有角色**，
于是 `localMeaningful()` 原样放行，开机自动 push 把手机刚备份的那份盖掉了。
**少了三个角色**，人设再也回不来。

## 规矩

**任何会让数据消失的指令，前面必须先带一句「先导出一份文件备份」。**

这几种话在这个 app 里都属于「会让数据消失」，一句都不许光秃秃地说出口：

- 「把 app 删掉重装」
- 「清一下浏览器数据 / 清缓存 / 无痕窗口试试」
- 「退出登录再登进来看看」（`signOut` 会清本机 x_）
- 「换台设备打开看看」（旧设备一开机就可能往云上推）
- 「点一下从云端恢复」（会覆盖本机）

正确的说法长这样：

> 先去 **设置 → 数据 → 导入与导出 → 导出全部数据**，存成 json 放桌面上。
> 存好了再删。

⚠️**「云端有备份」不能代替这一句。** 云是**一行 upsert，没有历史**：
被盖掉就是被盖掉了。只有落在她自己硬盘上的那份 json 是谁也动不了的。

## 判据一句话

**这条指令执行完，有没有哪一份数据只剩一个副本了？**

有 → 先导出。没有 → 才可以直接说。

## 顺带记下的两条

1. **「空的不许盖」挡不住「旧的盖新的」。** `localMeaningful()` 只问「有没有角色」，
   一台几个月前的旧设备完全过得去这道闸。v61.63 补了 `staleness()`：
   云端比本机最后一次同步新出一天以上，就不许静默推。
   立闸的时候要问的是**「我防的是哪一种坏情况，另一种呢」**。
2. **数据分几张表，被盖的往往只有一张。** 那次盖掉的只是 `saves` 这一份 blob；
   `memories`（行表，自带 char_ids）、`chat_archive`（按 char_id、只追加）
   一条都没少。所以事故之后**先查还剩什么，别急着说没了**——
   「找回失联的角色」（设置 → 数据）就是照这个思路做的：
   记忆和聊天还在，只是没人认领；用原来那个 id 把角色建回去就接回来了。
