# 四处一样喂（Lisa 2026-08-24 立）

**单人线上 / 单人线下 / 群聊线上 / 群聊线下，喂给模型的东西默认必须一样。**
除非某一处被【明确点名】需要特殊处理，否则任何一处有的层，另外三处都要有。

## 为什么立这条

她 2026-08-24 报：群里裴照川开始说霸总话，而同一个群里的双胞胎完全正常。
查下来不是霸总禁令的问题，是**群聊把人设砍到了 200 字**（单聊是全文），而且
群聊压根不走 `buildBundle`——印象卡、心情、好感度、长期记忆一层都没有。
他在群里只剩「一个古代王爷」这个标签，剩下的空白由训练先验补上，那就是网文霸总。

**截断对谁伤害大，取决于截断之后剩下的标签有多刻板。** 双胞胎是「现代年轻人」，
fallback 无害；王爷不是。

这已经不是第一次了，同一个形状反复出现：

| 什么时候 | 哪一处漏了 |
|---|---|
| v54.80 | 同人文没吃到线下那套叙事准则 |
| v55.52 | 线下没吃到小剧场那五条（镜头/成段/一拍） |
| v55.66 | 线下完全没有回声式反问的防线（禁令和刀都只在线上） |
| v55.86 | 群聊线上完全没有回声防线 |
| v55.87 | 群聊人设截断到 200 字、没有印象卡/心情/好感度 |
| v55.89 | 群聊三处私聊围栏都只挡「别人的私事」，没挡「自己的私事被端上台面」 |
| v55.90 | 群聊没有用户人设／情侣状态／年龄／此刻在做什么；霸总语气禁令只埋在单聊的行程块里当从句 |
| v55.91 | 群聊把模型放在【导演位】上（单聊是「完全代入『某某』」，群聊是「你在导演一个群聊」）；「彼此不熟就照不熟来」只写在两人旁观局那一支里 |
| v55.95 | 实时心情的更新指令写好了、声明了一次，然后【从没被引用过】——四处一个字都没收到 |
| v56.09 | 「每几轮自动抽取记忆」单聊线上／单聊线下／群线下都有，只有群线上没接——它只挂着 150 条才动一次的滚动总结 |
| v56.27 | 群聊线上没有一句话说过「同一个人可以连发好几条」——单聊靠 `word:string[]` 天然有，群聊那个数组是几个人共用的 |
| v60.27 | **通话（语音/视频）根本不在这张名单上** |
| v61.16 | **穿书也不在这张名单上** —— 反八股那一堆里，居高临下／三件套／语域跟场面走／回声禁令／内容边界，一条都没有 |
| v61.37 | **匿名信箱也不在这张名单上** —— 回声禁令／语域跟场面走／读懂这句话在做什么，三条都没有 |
| v61.47 | **解梦馆也不在这张名单上** —— 它自己拼 sys：人设截到 400 字、心情／好感／最近聊天／反八股**一条都没有** |

每次都是「这一层当初只写在一处，别处没跟上」。所以默认改成【四处一样】，
差异必须是**显式的、写着理由的**，不能是忘了。

## ⚠️通话是第五处（v60.27 补，她 2026-09-02 报）

她原话：「感觉语音视频没喂八股禁令进去」——是真的，而且比想的更彻底：

| | 单人通话 | 群通话 |
|---|---|---|
| 反八股 / 居高临下 / 三件套 / 内容边界 | ✅ 走 buildBundle 白得的 | ❌ 一条都没有 |
| 回声禁令 / 语域跟场面走 / 读懂这句话在做什么 | ❌ | ❌ |
| 人设 | ✅ 全文 | ❌ **砍到 160 字** |

病因是这条规矩自己：**它当初只列了四处，通话从来没在名单上**。
于是「四处都接上了」每次都是真的，通话每次都漏。
单人通话还捡到了 buildBundle 里那几层（那是白得的，不是有人想着给的）；
群通话自己从零拼 sys，什么都没有，人设 160 字——
比 v55.87 群聊变霸总那次（200 字）砍得还狠。

**电话是最容易滑回八股的场合**：话短、来回快、没有气泡可拆，
模型手上只剩「这种时候该说什么」。所以这一处尤其不能少喂。

以后查缺时，名单是【八处】：单人线上 / 单人线下 / 群聊线上 / 群聊线下 / **通话** / **穿书** / **匿名信箱** / **解梦馆**。
（小剧场、同人文、跑团、擂台是平行时空沙盒，另有各自的合法差异，见下。）

## ⚠️解梦馆是第八处（v61.47 补，她 2026-09-03 问）

她原话：**「人设心情最近聊天防八股那些有全部喂进去吗」**——答案是**一条都没有**。

这一处比前几处都薄：它**自己拼 sys**（`callAI` 直发），所以连 buildBundle
白送的那一份都没吃到：

| | 解梦馆（v61.47 之前） |
|---|---|
| 人设 | ❌ **截到 400 字** |
| 心情 / 好感 / 印象卡 / 记忆 | ❌ |
| 最近聊天 | ❌ |
| 反陈词滥调 / 居高临下 / 三件套 / 亲密反模板 / 内容边界 | ❌ |
| 回声禁令 / 语域跟场面走 / 读懂这句话在做什么 | ❌ |

400 字正是 v55.87「群里的王爷变霸总」那个数量级（那次是 200 字）。
**解梦这个题材尤其危险**：人设只剩一个标签时，空白由训练先验补上，
而这一题的先验就是【心理测试小作文】——「这个梦说明你内心渴望被理解」。
她要的是这个人用他自己的腔调胡说八道，不是一份通用解签。

改法照匿名信箱那次：换成 `runProbe({ voice: true })`，buildBundle 整份白得，
站位也从「分析师」换成「他本人在说话」；那三条只能靠调用点 push 的另外补上。

⚠️`runProbe` 要 `ctx`，所以 `ctxFor` 得从 App 传进这个组件——
**「换个入口就什么都没有」往往就是因为这一处压根没接上下文这条线**。

## ⚠️匿名信箱是第七处（v61.37 补，她 2026-09-03 报）

她原话：**「匿名信箱的 prompt 还是语气不对为啥」**。

病因还是这条规矩自己：**它当时列到六处，匿名信箱从来没在名单上**。
匿名箱走 `runProbe(..., { voice: true })`，所以 buildBundle 那一份是白得的
（反陈词滥调／居高临下／三件套／亲密反模板／内容边界／人设全文／心情／好感）。
漏掉的还是那三条**靠调用点一条条 push** 的：

| | 匿名信箱（v61.37 之前） |
|---|---|
| 回声式反问 `ECHO_QUESTION_BAN` | ❌ |
| 语域跟场面走 `REGISTER_FOLLOWS_SCENE` | ❌ |
| 读懂这句话在做什么 `ReplyPacing.reading()` | ❌ |

**这一处尤其吃亏，因为它手上全是问句。**
模型拿到一串问题逐条作答，最顺手的开口就是把人家的问题原样反问回来
（「我怕什么？」「变了？」），十条能有六条这么起头——那正是回声禁令要挡的东西，
而这一处一个字都没收到。语域同理：对着一屋子陌生人说话，和对着女朋友说话
本来就不是同一个分寸；没有那一层，他会拿主聊天的温度去答树洞。
第三条是「读懂这句话在做什么」：匿名提问里有一半是挑衅、试探、找茬，
不是真来要答案的；没有它，每一条都会被当成诚恳提问认真作答，那就是判词机器。

⚠️匿名箱有**两条路**（陌生网友那批 / 她自己攒的那一箱），
所以这三层写成了一个共用的 `anonBans()`——各写一份的话迟早只改一处（v56.09 那个形状）。

## ⚠️穿书是第六处（v61.16 补，她 2026-09-03 报）

她原话：「穿书这块是不是没有喂禁八股那一堆，一堆八股」——是真的，
而且**病因和通话那次一字不差：它当初就没在这张名单上**。
于是「五处都接上了」每次都是真的，穿书每次都漏。

穿书走 `narrativeCore({intimate:true})`，所以**白得**了去人机味、角色卡准则、
线下叙事准则、叙事反陈词滥调、亲密反模板、语气与年龄感锚。
漏掉的那几条，恰恰都是**别处一条条 push 进去**的（`buildBundle` 里那一串）：

| | 穿书（v61.16 之前） |
|---|---|
| 内容边界 `ContentBoundaries.prompt` | ❌ |
| 居高临下的训话腔 `CONDESCENDING_TONE_BAN` | ❌ |
| 语域跟场面走 `REGISTER_FOLLOWS_SCENE` | ❌ |
| 标准男友三件套 `STOCK_REPLY_BAN` | ❌ |
| 回声式反问 `ECHO_QUESTION_BAN` | ❌ |
| 读懂这句话在做什么 `ReplyPacing.reading()` | ❌ |

**判据**：一层规则是「靠调用点一条条 push 的」，还是「靠某个打包函数白送的」——
白送的那些换个入口自然就有；一条条 push 的，换个入口就一条都没有，
而且**不会留下任何能 grep 的痕迹让你发现它不见了**（v56.27 学到的那一条）。
所以查缺别顺着「这条规则写没写」找，先问**这一处是靠什么把这层拿到手的**。

穿书是平行时空沙盒（不读写主线记忆/好感/心情），但**反八股那一堆不是记忆，是文风地板**，
在哪儿都该有。沙盒身份不构成砍掉它们的理由。

v55.90 还多学到一条：**一层规则如果只作为某个可选块的从句存在，它就跟着那个块一起消失。**
「不许滑进居高临下的训话腔」当初写在【今天的行程】那一段里——角色今天没排日程，
schedNow 为空，整段不 push，这句也就没了；群聊更是从来不发行程这一段。
所以：**能独立成立的规则就让它独立成立**，别挂在别人身上搭便车。

v55.91 学到的是这条规律的另一半：**四处一样喂，喂的不只是【料】，还有【站的位置】。**
前面几版一直在补群聊缺的上下文层（人设全文、心情、好感、印象卡、情侣状态、年龄），
料补齐了，王爷在群里还是霸总——因为单聊的任务句是「完全代入『裴照川』」（你就是他），
群聊的任务句是「你在导演一个群聊」（你在旁边写他）。导演写「一个古代王爷」，
写出来的就是这个类型的通用样子。
（群聊也发 ONLINE_CHAT_RULE_V2 里那句「完全代入当前角色」，但群里有三个人，
「当前角色」没有指代对象，这句话是空转的——**一句话在别处成立，不等于在这处也成立**。）

v56.27 补的是另一种走法：**同一层能力，两处靠的机制不一样时，其中一处可能压根没有那个机制。**
「一句话拆成几条气泡」在单聊里根本不是一条规则——`word` 是 `string[]`，那个数组从头到尾只属于
一个人，多放几个元素天然就是多发几条。群聊的数组是【几个人共用】的，一个人要连发就得重复出现、
每次都填自己的 name；这件事没有任何一句话说过，模型只能把「消息的数量」理解成「几个人说话」。
所以查缺的时候，别只顺着「这条规则写没写」找——**先问这一处是靠什么把这层实现出来的**，
靠结构白送的那层，换个结构就没了，而且不会留下任何一条可以 grep 的规则让你发现它不见了。

v55.95 是同一个形状的极端版：**声明了但没人引用，比压根没写更坏**——
看代码以为已经在发了。旁边那条心声（`_normalThoughtTurnHint`）是拼进去的，
所以心声一直在动、心情十三个小时纹丝不动。
新加一层规则时，光看到常量存在不算数，要顺着拼接链一路看到它真的进了 system。

**砍层的唯一合法理由**：这一层**大多数轮次根本用不上**（比如论坛回声——
十轮里九轮用不上，v56.14 改成按需触发）。这是「这一轮用不用得上」的问题。

除此之外，该给的层一律给足。人设尤其要给足：v55.87 那次群里的王爷变霸总，
病因就是**人设只剩 200 字**（只剩「一个古代王爷」这一个标签，空白由训练先验补上），
**放宽到 6000 字是修好它的那一步**。v55.91 那次是**站位**（模型被放在导演位上）。
两次的病因都不是上下文的总量。

## ⚠️还有「怎么发」那一半（v64.62 补，她 2026-09-06）

这条规矩从头到尾管的是**发什么层**。可同一段字**放在 system 里还是 user 里**，
上游读起来是两件事——「Ta 眼里」那两枪就是栽在这儿：料全对，摆错地方，被拦了几个月。
见 `prompt-send-shape.md`。**查缺时两样都要问：这一层给了没有？给的时候摆对地方没有？**

## 落地要求

1. 新加任何一层（提示词常量、兜底刀、状态字段、上下文块）时，四处都要接上。
   接不上的那一处，在代码里写清楚为什么。
2. 已知的**合法差异**（有理由，不算漏）：
   - **言秋（`engineerEyes` / `notRoleplay`）**：他不是被扮演的角色，扮演类规则一律不发。
   - **封闭群（`!memoryInterop`）＝只进不出**（她 2026-08-24 定的）：
     **读一律给**——记忆库、长期记忆、印象卡、长出来的自我、人设全文、心情、好感，
     角色在哪儿都得是完整的自己，不能一进闭群就退化成一张标签；
     **写一律封死**——闭群里发生的事不写回记忆库、不动好感、不动心情与状态卡、
     不驱动朋友圈/论坛/悄悄话、不结算钱包、不回流进单聊（群回声）。
     唯一还归互通群的读项是【实时私聊窗口】：闭群那边有自己的 preJoin（入群前私聊）
     当这一档，两者不叠加，否则同一段私聊会进两遍。
     一句话：**闭群是平行沙盒，读主线、不写主线。**
   - **群里的行程**：单聊发整张【今日安排】，群里只发「此刻正在做什么」这一行——
     一人一份完整行程会撑爆上下文，而她按次计费。决定语气和连贯性的是「此刻」那一句。
   - **小剧场 / 同人文**：平行时空，不引用主线记忆与关系。
   - **跑团**（v57.13 起）：同小剧场——平行时空沙盒，只读人设（全文、每人封顶
     6000），不读写主线记忆/世界书/好感/心情；游戏属性与 HP 是沙箱数值，不进状态卡。
   - **数字生命**：不发扮演三件套。
3. 群里每位成员的私有层，必须落在**那位成员自己那一段**里，并带隐私围栏
   （见 `interop` 的 memLines 与 preJoin 的写法）——绝不许合成一块共享注入。
4. 人设不许再用固定字数截断。按在场人数分预算（`groupPersonaBudget`），
   每人封顶 6000 字、总预算 30000、地板 1500——她的人设普遍 4500+，
   五人以内的群谁都不该被砍。
5. 加任何一条【写】主线的动作（记忆、好感、心情、状态卡、钱包、动态计数器）时，
   先问一句「封闭群里发生这件事，该不该影响主线」。默认答案是不该。
