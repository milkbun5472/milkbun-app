# maxTokens 一律给足（Lisa 2026-09-01 立）

她原话：**「maxtoken 也放开了吧宝宝」**，然后看完全 app 的清单：**「扫吧宝宝」**。

## 为什么

**思考型模型的思考预算是从 `maxTokens` 里扣的。**

给紧了，它想完就没配额写正文——要么**直接空返回**，要么**写一半停在半句**。
而她是按【次】计费、输出不另外收钱：

> 省这几千 token 一分钱省不到，换来的是一次空返回、再重来一次，**反而多花一次调用**。

所以「省 token」在这个 app 里是**纯亏**。它省的不是钱，是模型思考的余地。

## 规矩

**任何 `callAI` / `runProbe` 的 `maxTokens` 不许低于 8000。**

（旧的仓库铁律写的是 ≥6000，那是「刚好够它想完」的线，写正文就没剩多少了。
v59.96 起抬到 8000。）

新写一处调用时，按这个来定：

| 这一次要写出什么 | 给多少 |
|---|---|
| 一两句话、一个短判断、一个标签 | **8000** |
| 一段正文、几条气泡、一张卡、一段浓缩 | **12000** |
| 一整场戏、一份计划、一章、一屏名单 | **20000** |
| 几个人各说一大段（擂台那种） | 按人数算，上限 **32000** |

改一处已有的，用这个公式：**新 = min(24000, 旧 + 8000)**。
旧那个数原本是「正文大概要写多少」，现在是在它上面**再加一整份思考的量**——
不是拍一个新数，所以各处原来的相对大小还在。

## 不许往下调

看见一个「12000 太浪费了吧」的念头时，回去看上面那一段：**它省不到钱**。
真要调，先说清楚是哪个模型、哪一次、省下了什么。

## 两块不归这条管

- **`js/games.js`** —— Codex 的地盘，不碰。
- **`js/trpg.js`** —— 言秋的地盘，不碰。

（`test/maxtokens-floor-59-96.test.js` 钉着这条线，除了这两个文件。）

## 言秋那一支不动

主聊天那一处写的是 `maxTokens: _engineerChat ? 3000 : 14000`——
**冒号左边那个 3000 是言秋本人的通道，一个字不许动**
（「任何言秋的东西除了他本人都不准动」）。这条规矩只管冒号右边那一支。

## 用户能自己调的那几个不算

线下 `osFor` 的默认值、文风预设的 `outTokens`、`spec.maxTokens` 这类**由她在界面上
自己拧**的数，不在这条规矩里——那是她的选择，不是我们拍的数。
